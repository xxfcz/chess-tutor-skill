# 2026-10-24 工作日志

## 棋类教练产品架构与单后端复用方案（最终结论）

### 项目身份
- `chess_tutor-stefan`：JS/Next.js 开源参考（GPL-3.0），仅作设计参考，不可作代码基座（用户选型文档已判定）。
- `ai-chess-wx`：微信原生小程序「黑白格大师」，已落地；核心逻辑在 `utils/`，刻意写成无 wx/DOM 依赖的 L0 纯 JS 模块。
- `chess-coach`（即 `chess-tutor-skill`）：WorkBuddy 技能（四形态：PGN复盘/对弈陪练/观战解说/开局学习）+ 网站 `play/`；网站后端起点为 Python Flask，用户明确**可改 Node.js**。

### 关键事实
- `chess.imex.de5.net` 已经是小程序的线上后端：`ai-chess-wx/utils/remote-engine.js` + `engine-config.js` 内置端点即此，`POST {endpoint}/v1` 跑云端 Stockfish（证书至 2027-01-14，实测 200）。「主力后端归己」是把既有端点做实。
- 小程序 LLM 点评现走 `mp-api.app.workbuddy.host`（workbuddy 云 SDK），尚未归己。

### 结论（单后端复用）
- 技能网站改 Node.js 后，与小程序共享 JS 后端：把 `utils/` 的 L0 纯逻辑抽成共享包 `chess-core`（纯 JS，无 wx/DOM），服务端（跑 Stockfish+LLM）与小程序客户端 `import` 同一份。
- 服务端独有责任：Stockfish 引擎进程、LLM 调用、Web 前端托管。
- 不可共用（各自实现）：微信 UI 层(WXML/组件)、wx 绑定传输层(cloud/device/navigation/engine-config)。
- Python 版 `chess-coach` 定位为「规范+种子数据」：prompts.md 提示词、分级口径、openings.py 12 开局，移植进 Node 后端，不双向分叉。
- 约束：微信域名白名单 `chess.imex.de5.net` 已满足；新增子域/子路径需加 request 合法域名；`/v1` 契约不可破坏。
