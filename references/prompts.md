# LLM 教练层 · 提示词与解释设计参考（路线 A）

> 本文件是“AI 教练”技能的 **LLM 层设计参考**，提炼自 **CheckPause**（Stockfish+LLM 教练）、**CS357 Chess AI Coach** 教程、以及 **Chess Coach Turning Points** 数据集。
> 设计原则：**真相来自引擎（Stockfish）+ 规则，解释来自 LLM**。LLM 不计算棋，只把引擎数据翻译成有依据、有教学结构的人类语言。

---

## 0. 走子分级与精度评级体系（参考 CheckPause）

分析引擎（`scripts/analyze.py`）先把每一着打标签，LLM 的解释围绕这些标签展开：

### 走子标签（11 类，CheckPause 原版；我们分析层实际计算 Best/Good/Inaccuracy/Mistake/Blunder，其余供参考）
| 标签 | 含义 | 本技能是否计算 |
|---|---|---|
| Brilliant | 牺牲/非常规但最优 | 参考（靠牺牲检测，可选） |
| Great / Best | 接近引擎首选 | ✅ Best（损失≤10cp 且为首选） |
| Excellent / Good | 小损失 | ✅ Good（损失<40cp） |
| Book | 开局书着 | 以阶段代替 |
| Forced / Only move | 唯一不亏的着 | 参考（需 multipv） |
| Inaccuracy | 损失 40–100cp | ✅ |
| Mistake | 损失 100–300cp | ✅ |
| Miss | 错失关键机会 | 以战术原因代替 |
| Blunder | 损失 ≥300cp | ✅ |

### 五档精度评级（CheckPause 原版，按 ACPL 平均每着损失分）
| 档位 | ACPL 区间 | 含义 |
|---|---|---|
| Optimal | ≤10 | 近乎完美 |
| Precise | 10–30 | 精准 |
| Competent | 30–60 | 称职（多数成人进阶玩家区间） |
| Steady | 60–100 | 尚可，波动大 |
| Volatile | >100 | 不稳，失误频繁 |

> 本技能对 ACPL 的损失做 **400cp 封顶**，避免“输定局面每步都被判大损失”的失真（与 Lichess 等主流做法一致）。

## 1. 逐着点评提示词（参考 CS357 `getAICommentary`）

> 用于对任意一着生成 2–4 句教练式点评。**只评这一着，绝不剧透后续。**

```
你是一位专业的国际象棋教练。玩家执 {color}，估算等级分约 {elo}。
你正在分析刚走完的一步棋，结合整局到此为止的上下文。

整局 PGN（以正在分析的这步结尾）：
{pgn_so_far}

走子前的局面（FEN）：{fen_before}
刚走的着法（SAN）：{san}
走子后的局面（FEN）：{fen_after}
引擎对该步的评估（玩家视角，单位：兵）：损失 {loss_cp} cp，标签 {label}。
最佳着法（引擎）：{best_move_san}。

要求：
1. 只评价“这一步”，结合整局上下文判断它是好棋、不精确、失误还是严重失误。
2. 若非最优，明确指出一步更好的着法并解释为什么（用引擎评估支撑，不要凭空发挥）。
3. 绝对不要预测、建议或暗示任何后续的着法、应手或变化。
4. 控制在 2–4 句话。语气鼓励但诚实。
```

设计要点（直接沿用 CS357）：
- **角色先行**：`You are an expert chess coach` 定语气。
- **给具体状态而非模糊描述**：传入走子前后 FEN、SAN、整局 PGN，让模型基于真实局面推理。
- **显式范围限制**：`Analyze ONLY the move just played` + `Do NOT predict future moves`——否则模型会剧透开局线，既破坏学习又常出错。
- **长度与温度**：2–4 句、temperature 0.2，教练语气应稳定可复现。

## 2. 结构化评估提示词（JSON，驱动评分条/精度条）

> 用于需要数值（而非段落）的场景：评估条、Elo 估计、胜率。模型输出必须可解析。

```
你是国际象棋引擎。给定下面这个 FEN，估计白方视角的局面评估，单位：兵
（正=白优，负=黑优）。只返回一个 JSON 对象，如 {"eval": 0.5}。
FEN: {fen}
```
输出清洗：`text.replace(/```json|```/g, "").trim()` 后 `JSON.parse`，失败回退 0。

## 3. 错题访谈提示词（参考市场文档“错题本升级为错题访谈”）

> 定位错误性质：**计算错 / 知识盲区 / 习惯问题**。用于把“你走错了”升级为“你为什么错”。

```
你正在辅导一位棋手复盘他的一步走错（{label}，损失 {loss_cp} cp）。
走子前 FEN：{fen_before}；他走的：{san}；引擎最佳：{best_move_san}。

请用 3 个短问题引导他回忆当时的思考过程（不要直接给答案）：
1. [问他是否看到了对手的某一个威胁/应手]
2. [问他当时在比较哪几个候选着法]
3. [问这一步属于：没算到 / 不知道该计划 / 习惯性随手？]
最后用一句话总结：这一步最可能是“计算错 / 知识盲区 / 习惯问题”中的哪一类，并给出下次避免的 1 条具体提示。
```

## 4. 成长画像叙述提示词（把多维画像写成“人物小传”）

> 输入：profile.json 的 dimensions + weakest。输出：一段有温度的能力画像。

```
你是一位棋类 AI 教练，正在为学员写“能力画像小传”。以下是他最近 N 局的结构化数据：

- 综合精度 {accuracy}%，评级 {tier}，ACPL {acpl}
- 各维度评分（0–100，越高越好）：{dimensions_json}
- 最弱三项：{weakest_json}

请写成 3–5 句话的画像：用具体数字说话，指出 1–2 个真实亮点（已经不错的维度），
并点明最该优先补强的方向。语气像一位了解他的私人教练，不要列清单，要说“人话”。
```

## 5. 训练计划提示词（诊断 → 开方 → 练习 → 复测）

> 输入：weakest 三项 + key_errors。输出：一周针对性训练计划（市场文档里程碑）。

```
你是私人棋类教练。学员画像最弱三项：{weakest_json}。
他反复出现的错误类型：{key_error_types}。

请生成一份“一周针对性训练计划”，务必闭环：
1. 诊断：用一句话说明这周为什么练这三项。
2. 处方：每天 1 个主题（围绕最弱项轮换），给出练习形式（战术题/残局/对局/复盘）+ 题量/时长。
3. 练习：明确每天做什么、做多少。
4. 复测：周末用 1 局新对局或 10 题专项，验证对应维度评分变化，给出可量化目标。

要求：计划必须可落地（成人每天 20–40 分钟），不要空泛口号。按“周一～周日”表格输出。
```

## 6. 对话追问（Play Coach 风格）

> 学员可就任意一步继续追问，如“这步 Nf5 我为什么不行？”。上下文是屏幕上已展示的引擎数据，回答必须 **基于这些数字**，不幻觉。

```
（系统已向学员展示：PGN、每步评分与最佳着法、评估条）
学员问：“{question}”
请基于已展示的引擎数据回答，像教练对话一样接着聊；若问题涉及尚未分析的数据，明确说明“这需要再算一步”。
```

## 落地约定（技能内使用）
- **引擎数据永远先行**：所有解释必须引用 `{loss_cp}`、`{label}`、`{best_move_san}` 等结构化字段，禁止凭空捏造变例。
- **不剧透**：任何点评都只谈“已发生的这步”。
- **可复现**：教练生成类提示词 temperature≤0.3；结构化评估 temperature=0。
- **幻觉兜底**：引用具体着法/评估前，先用 `scripts/analyze.py` 得到真实数据；无法确认时显式声明。
